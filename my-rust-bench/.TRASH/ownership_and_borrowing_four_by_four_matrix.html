Theoretical Foundations

How Rust's borrow checker and functional uniqueness typing systems map to this matrix.

1. Linear Uniqueness ({1})

Represented by BoxList<T>. Exactly one handle exists. The transformation consumes the heap cell and repoints the forward link backward in-place. No reference counter is required (0 bytes overhead), and stack frames are completely eliminated via Tail-Call Optimization (TCO).

2. Exclusive Borrowing (&mut)

A temporary permission to mutate an existing location without transferring ownership. The pointer flip occurs in-place, preserving caller identity. The function returns either a reborrowed &mut or downgrades to an immutable & view.

3. Perceus Copy-on-Write (Dynamic FIP)

Represented by RcList<T>. When strong_count == 1, the cell is statically unique at that moment, allowing in-place pointer flipping without allocation. When strong_count > 1, it duplicates only the shared node, achieving amortized in-place functional programming.

4. Aliasing XOR Mutability Theorem

Cell [Row 4, Col 2] illustrates why &T → &mut T cannot exist directly in safe Rust. If multiple readers view &BoxList, turning it into &mut would create data races and dangling pointers. Safe mutation requires taking a separate exclusive target destination slot.
